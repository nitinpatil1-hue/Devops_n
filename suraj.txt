Git also called as SEM (Source Code Management Software / repository management software / versioning management software)

- working directory --> staging area (test stage) --> commit
- when performed "git add <filename>" its gets copied to stating area and can be restored back to working directory if the original copy gets deleted, so staging area can be used as a backup.


whats the purpose of staging area:
- The staging area is a rough draft or a loading dock for your next save point.Instead of saving all your work at once, you pick and choose exactly which changes go into your next commit.
- to select exactly what you want to commit
- we can later restore files back to working directory if not needed

	Working Directory: Changes you are making -----> touch <filename>
	Staging area: changes selected for the next commit ------> git add <filename>
	commit: permanently recorded commits -------> git commit -m "message"


- to remove files from staging area:

		$ git rm --cached <filename>

what is alias record?
- An alias record is a custom Domain Name System (DNS) record that lets you point your root domain (like example.com) to a hostname
- An ALIAS record is a special type of DNS setting that lets you point your main website address (like example.com) to another domain name instead of a fixed IP address.

Task: How to run the project via Pipeline


- PIPELINE: automated sequence of steps that takes application code from development, testing, deployment

- Jenkins -> Add new item -> name (my a-firstpipline) -> Pipeline

- Pipeline -> CODE -> SCRIPT -> when we write anything in script filed, jenkins files gets created at the background, it has its structure like blocks, directives etc, it has JAVA Based structure and used the groovy language (its a java based language)

- We can also shell script instead of groovy language.
- Adding code:

	There are 2 methods to write the pipeline, 
	1. Scripted Pipeline
	2. Declarative Pipeline

Difference between Scripted & Declarative Pipeline:

- If the code starts with word "pipeline" then its declarative pipeline.
- Scripted pipeline will start with "node" word.


- Pipeline block starts with '{' and ends with '}':

example:

		pipeline{


		}
		

- we can add more blocks to pipeline, these are called as stages:

		pipeline{

			stages{

				stage1 ('print'){

					step1 (actual code)

				}

				stage2 ('cloning'){

					step2 ()
				}

				stage3 ('deploy'){

				}
		}
	}


Blocks:

Pipeline
	|- 
- these stages are basically the functions, meaning we can declare it once and call it multiple times in a code
- print, cloning are the names of function.


Example of pipeline: simple hello world pipeline code:

	pipeline {
	    agent any 

	    stages {
	        stage('Hello') {
	            steps {
	                echo 'Hello World'
	            }
	        }
	        stage('Goodbye') {
	            steps {
	                echo 'Goodbye World'
	            }
	        }
	    }
	}

- it is necessary to add "pipeline", "agent any" etc words to the pipeline.

- Jenkins also has the Credentials feature
- We can store credentials of multiple servers to the jenkins, which we can later used in freestyle, pipelines code
- The Jenkins Credentials feature is a built-in, secure storage system designed to keep your sensitive data hidden and protected.
- Instead of typing passwords, private keys, or API tokens directly into your Jenkins scripts or code (which is a major security risk), you store them securely inside Jenkins. You can then reference them in your build jobs using a unique ID.

Jenkins -> Manage Jenkins -> Security -> Credentials

- There are multiple options to add the credentials, such as:

	- username & password
	- GitHub app
	- SSH Username & private key
	- secret file
	- secret text
	- Certificate

Adding nodejs server to the pipeline, code will now deploy to app server(nodejs) directly.

1. Create app server
2. install nodejs package
3. add sample code

	# pwd
	/opt/nodejsproj

	# cat app.js 
	const http = require("http");

	const server = http.createServer((req, res) => {

	    if (req.url === "/" && req.method === "GET") {
	        res.writeHead(200, { "Content-Type": "text/html" });
	        res.end("Hello World");
	    }

	});

	server.listen(3000, () => {
	    console.log("Server running on port 3000");
	});
